# 工程的所有技术细节通俗解释、公式推导与论文研究依据

## 1. 这份文档怎么用

这份文档的目标不是给你“代码说明书”，而是给你一份可以直接转成论文文字的技术解释。

它会同时回答三类问题：

1. 这个工程到底在做什么
2. 数学上它是怎么计算的
3. 这些计算在论文里可以依据什么来写

## 2. 工程总目标：一句话说清楚

这个工程要做的事情可以概括成一句话：

`在一个低轨卫星通信场景里，把星座、地面站、链路预算、干扰、路由、吞吐、时延和合规性统一放在一个系统级框架中去评估。`

也就是说，它不是单纯：
- 做一个链路预算

也不是单纯：
- 做一个深度学习识别器

而是把这些东西串成一条完整链：

1. 构造星座
2. 计算星地几何
3. 计算信号与干扰功率
4. 计算上下行链路指标
5. 合成端到端结果
6. 判断是否满足工程约束
7. 再用识别模块做辅助解释

## 3. 星座与轨道：工程是怎么理解“卫星系统”的

对应代码：
- `emcDefaultConfig.m`
- `LEO_StarNet_EMC_V7_0_Engineering.m`

### 3.1 基本轨道参数

工程里定义了：
- 地球半径 `Re = 6371e3`
- 地球引力常数 `mu = 3.986004418e14`
- 星座高度 `h`
- 轨道半长轴 `a = Re + h`

这表示：
- 工程用的是标准圆轨道近似
- 不考虑复杂摄动

### 3.2 轨道周期

代码里：

```matlab
T_orbit = 2*pi*sqrt(a^3/mu);
```

这就是经典圆轨道轨道周期公式：

\[
T = 2\pi \sqrt{\frac{a^3}{\mu}}
\]

含义很直观：
- 轨道越高，周期越长
- 引力常数固定时，轨道周期由轨道半径决定

### 3.3 星座结构

工程当前星座是：
- `NumPlanes = 12`
- `SatsPerPlane = 8`
- 总数 `Nsat = 96`

并且通过：
- 轨道面编号
- 槽位编号
- 相位因子 `FPhasing`

来构造一个类似 Walker 的规则星座。

## 4. 星地几何：工程怎么知道哪颗星能看见用户

对应代码：
- `LEO_StarNet_EMC_V7_0_Engineering.m` 中 `aer(...)` 相关部分

工程对每一颗卫星、每一个时刻计算：
- 方位角 `az`
- 仰角 `el`
- 斜距 `range`

### 4.1 可见性判决

代码里是：

```matlab
visU_all = elU > elMaskDeg;
visG_all = elG > elMaskDeg;
```

意思是：
- 只有当卫星仰角高于门限 `ElMask` 时，链路才认为“可见”

这个判决在工程上很常见，因为：
- 太低的仰角会有严重遮挡、低增益和传播问题

### 4.2 径向速度

代码用距离差分近似：

\[
v_r(k) \approx \frac{r(k+1)-r(k)}{\Delta t}
\]

再通过滑动平均让它更平稳。

这一步是为了后面的多普勒计算。

## 5. 链路预算：工程怎么计算信号功率

对应代码：
- `fspl_dB_vec.m`
- `emcPrecomputeLinkPower.m`

### 5.1 自由空间路径损耗

代码公式：

```matlab
PL = 32.45 + 20*log10(d_km) + 20*log10(freq_MHz);
```

这就是常见的自由空间路径损耗公式：

\[
PL_{\mathrm{FS}}(dB)=32.45+20\log_{10}(d_{\mathrm{km}})+20\log_{10}(f_{\mathrm{MHz}})
\]

含义：
- 距离越远，损耗越大
- 频率越高，损耗越大

### 5.2 接收信号功率

工程的接收信号功率本质上用的是：

\[
P_r(dBm)=EIRP(dBm)-PL(dB)+G_r(dB)
\]

其中：
- `EIRP` 是发射端等效全向辐射功率
- `PL` 是路径损耗
- `Gr` 是接收增益

### 5.3 同频干扰功率

工程还定义了干扰端等效功率：

\[
P_i(dBm)=EIRP_i(dBm)-PL(dB)+(G_r-\Delta_{\mathrm{penalty}})
\]

这里 `InterfPenalty_dB` 表示：
- 由于非理想指向或复用隔离带来的干扰罚损

### 5.4 聚合同频干扰

代码按复用簇求和：

\[
I_{\mathrm{CCI},c}(k)=\sum_{n\in \mathcal{C}_c} P_{i,n}(k)
\]

也就是：
- 同一个复用信道里的所有“可见干扰卫星”功率被聚合

## 6. jammer：工程怎么把“EMC干扰”变成通信可计算量

对应代码：
- `jammerPatternLin.m`
- 主程序中 `pJ_base_mW` 和 `pJsum_base_mW_DL`

### 6.1 jammer 基底功率

先算：

\[
P_{J,\mathrm{base}}(dBm)=EIRP_J(dBm)-PL_J(dB)+G_r(dB)
\]

### 6.2 离轴方向图

代码中方向图是分段的：

1. 主瓣区：

\[
G(\theta)=G_{\mathrm{main}}, \quad \theta \le \theta_{\mathrm{main}}
\]

2. 旁瓣过渡区：

\[
G(\theta)=G_{\mathrm{main}}+\alpha(\theta)\left(G_{\mathrm{side}}-G_{\mathrm{main}}\right)
\]

3. 远离主瓣时：

\[
G(\theta)=G_{\mathrm{floor}}
\]

最后转成线性功率系数：

\[
g(\theta)=10^{G(\theta)/10}
\]

### 6.3 jammer 到接收端的有效功率

于是：

\[
P_{J,\mathrm{eff}}(k)=P_{J,\mathrm{base}}(k)\cdot g(\theta_k)
\]

对多个 jammer 求和就得到：

\[
J(k)=\sum_m P_{J,m,\mathrm{eff}}(k)
\]

### 为什么这很重要

因为 EMC 不是抽象标签，而是：
- 真正注入接收端功率平衡的一项

这就把“EMC问题”真正转换成了“通信质量下降问题”。

## 7. 上下行与端到端：工程怎么从功率走到结果

对应代码：
- `simulateStarNetV7.m`
- `emcCombineE2E.m`

## 7.1 SINR

代码核心思想：

\[
\gamma(k)=\frac{P_S(k)}{P_I(k)+P_J(k)+P_N}
\]

然后转成 dB：

\[
SINR_{dB}(k)=10\log_{10}\gamma(k)
\]

### 直观理解

- 信号越强越好
- 干扰和噪声越大越差
- 这是整个通信质量评价的基础

## 7.2 BER

工程用的是 QPSK 近似误码率：

\[
BER(k)=\frac{1}{2}\operatorname{erfc}\left(\sqrt{\frac{\gamma(k)}{2}}\right)
\]

这不是一个完整的编码后误码模型，而是：
- 一种系统级代理公式

## 7.3 吞吐

工程用的是 Shannon-like 代理：

\[
\eta(k)=\min\left(\log_2(1+\gamma(k)),6\right)
\]

\[
THR(k)=B \cdot \eta(k)\cdot 0.8
\]

其中：
- `6` 是人为上限
- `0.8` 是效率折减因子

所以这一步的含义不是：
- 精确空口实现

而是：
- `系统级吞吐代理`

## 7.4 BLER

代码里：

\[
BLER(k)=1-(1-BER(k))^{BLK}
\]

这里 `BLK=1024`。

这是一个常见的近似：
- 假设比特错误近似独立
- 估计一个块里至少有 1 个错误的概率

## 7.5 多普勒

代码：

\[
f_D(k)=-\frac{v_r(k)}{c}f_c
\]

其中：
- `v_r` 是径向速度
- `f_c` 是载频
- `c` 是光速

多普勒变化率再用差分得到：

\[
\dot f_D(k)\approx \frac{|f_D(k)-f_D(k-1)|}{\Delta t}
\]

## 7.6 端到端吞吐与时延

工程把端到端吞吐定义为：

\[
THR_{E2E}(k)=\min\left(THR_{DL}(k), THR_{UL}(k)\right)
\]

这很符合工程直觉：
- 上下行任何一边拖后腿，系统体验就会被拖后腿

时延用：

\[
Delay(k)=\frac{r_U(k)+r_G(k)+d_{ISL}(k)}{c}
\]

其中：
- `rU` 是用户到服务星距离
- `rG` 是网关到网关星距离
- `dISL` 是星间最短路距离

## 8. 路由：工程怎么把星间网络纳入系统结果

工程不是做完整网络协议仿真，而是做一个清晰的工程代理：

1. 用图模型表示 ISL
2. 用 `shortestpath` 求最短路
3. 把最短路长度换算成传播时延

这一步的优点是：
- 简洁
- 足够表达端到端瓶颈
- 适合系统级扫描

## 11. 干扰识别模块：它在工程里到底是什么角色

对应代码：
- `generateDatasetSimpleSTFT.m`
- `trainLeNetSTFT.m`
- `classifyInterferenceTimeline_powerSampler.m`

### 11.1 本质

它不是：
- 主链通信求解器

而是：
- `辅助解释模块`

也就是说：
- 主链先算出 `PS / PI / PJ / PN`
- 再把这些功率量映射成 IQ
- 再做 STFT
- 再做 LeNet 分类

### 11.2 STFT 图像

代码核心是：

\[
S(t,f)=\text{spectrogram}(r)
\]

\[
P(t,f)=|S(t,f)|^2
\]

\[
I(t,f)=10\log_{10}(P(t,f)+\epsilon)
\]

再归一化并 resize 成 `128 x 128` 图像。

### 11.3 当前真实问题

当前识别问题不是简单“网络太弱”，而是：

1. 训练样本是规则合成
2. 推理样本来自真实主仿真功率
3. 标签逻辑原本没有充分考虑 `Ps`

这部分已经在：
- `06_识别模块问题与改进`

里做了完整分析。

## 15. 最后一段：你可以怎么把它写成论文

如果把整套工程通俗地压成论文语言，可以这样理解：

我们先用一个规则 LEO 星座把“车载用户—卫星—网关”的时变几何关系建立起来；然后用链路预算把每个时刻的信号、同频干扰、jammer 和噪声都映射成可计算功率；再用这些功率去统一计算上下行链路的 `SINR / BER / BLER / 吞吐 / 多普勒 / 时延`；最后把上下行合成端到端结果，并对照工程门限判断系统是否满足 EMC 与通信要求。  

这就是当前工程最本质的研究价值：

`它把卫星场景、通信链路、EMC 干扰和工程判据放进了同一条可运行、可落地、可写成论文的系统级评估链。`
