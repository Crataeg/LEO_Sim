# 干扰识别模块问题分析

## 1. 结论先行

结论非常明确：

1. `训练样本基本是我们自己人工合成的，不是实测数据，也不是从主仿真真实抓出来的原始IQ样本。`
2. `最终 12 张关键帧截图识别率低，不等于模型一定“训练失败”，更大的问题是训练域和推理域不一致、标签定义本身就偏弱。`
3. `当前 12 张关键帧文件名统计出来的识别正确率是 5/12 = 41.7%。`

## 2. 训练样本是不是“臆造”的

答案：`是，基本上是人工规则合成。`

## 2.1 数据集是代码自己生成的

训练集入口：
- `generateDatasetSimpleSTFT.m` 第 `1-20` 行

关键点：
- 第 `7-9` 行只设定了人工离散的 `SNRdB_list=[-5 0 3]` 与 `JSR_dB_list=[0 3 6 9 12]`
- 第 `17-19` 行直接调用 `genSplitSimple(...)` 生成训练/验证/测试集

也就是说：
- 数据不是从真实星座数据来
- 也不是从主平台真实最劣工况时间轴里截取
- 而是代码自己批量造出来的

## 2.2 具体是怎么“造”的

在：
- `genSplitSimple.m` 第 `6-26` 行

流程是：
- 先生成一段基带 QPSK：第 `10-11` 行
- 加 AWGN：第 `13-16` 行
- 再按类别随机生成干扰：第 `18-20` 行
- 最后直接转 STFT 图片：第 `22-26` 行

这说明训练集本质上是：
- `QPSK + AWGN + 规则干扰模板`

## 2.3 干扰类别本身是人工定义的

类别定义在：
- `generateDatasetSimpleSTFT.m` 第 `2` 行：`none / tone / pbnj / mod`

具体类别参数在：
- `randomJammerCfgSimple.m` 第 `1-21` 行

里面是完全人为规则：
- `tone`：随机单音频点，第 `6-8` 行
- `pbnj`：随机带通起点和带宽，第 `9-13` 行
- `mod`：随机频移和突发占空比，第 `14-17` 行

## 2.4 干扰波形也是规则生成的

在：
- `genJammerSimple.m` 第 `1-27` 行

这里分别用：
- 单音指数信号：第 `6-9` 行
- 带通噪声 `fir1 + filter`：第 `10-14` 行
- 突发调制信号：第 `15-23` 行

所以从严格意义上说：
- `训练样本确实是“自己造的”`
- 更准确的学术表述应是：
  - `基于规则的合成训练数据`
  - 而不是 `实测数据训练`

## 3. 为什么最终 12 张关键帧识别率低

## 3.1 先给结果

当前导出的关键帧文件名是：
- `sim_keyframe_01_k0001_mod_none.png`
- `sim_keyframe_02_k0007_mod_none.png`
- ...
- `sim_keyframe_12_k0656_mod_none.png`

按文件名里的 `true_pred` 统计：
- 正确 `5`
- 总数 `12`
- 准确率 `41.7%`

这批关键帧里，错误主要表现为：
- `mod -> none`
- `tone -> none`

也就是说：
- 模型经常把“有干扰但不够显著”的样本判成 `none`

## 3.2 第一层原因：训练域和推理域根本不是一回事

### 训练域

训练域来自：
- `genSplitSimple.m` 第 `10-24` 行

它的信号构成是：
- 单一 QPSK 期望信号
- 单一规则型 jammer
- AWGN

### 推理域

推理域来自：
- `classifyInterferenceTimeline_powerSampler.m` 第 `34-83` 行
- `sampleIQFromPowers.m` 第 `1-111` 行

它的样本不是“单类干扰模板”，而是：
- 真实主仿真导出的 `PS / PI / PJ / PN`
- 其中 `PI` 是共信道干扰
- `PJ` 还是由连续 `InfoCode` 混合生成的

所以推理时看到的是：
- `期望信号 + 共信道调制干扰 + 混合形态 jammer + 噪声`

而训练时看到的是：
- `期望信号 + 单一离散 jammer + 噪声`

这就是典型的 `domain gap`。

## 3.3 第二层原因：训练集是假设“单一类别”，推理集却是“连续混合类别”

在训练集里：
- 类别是离散的 `tone / pbnj / mod`

但在推理时：
- `sampleIQFromPowers.m` 第 `37-96` 行
- 明确把 jammer 写成连续混合：
  - `tone component`
  - `pbnj component`
  - `mod/bursty component`

混合权重来自：
- `jammerMixtureWeightsFromInfoCode.m` 第 `1-26` 行

也就是说，推理时 jammer 本来就是：
- `tone + pbnj + mod` 的连续组合

但最后却被强行压成一个离散标签，这会天然造成误差。

## 3.4 第三层原因：真值定义本身就不稳

当前“真值”并不是人工标注，也不是已知注入标签，而是代码推断出来的粗真值：
- `classifyInterferenceTimeline_powerSampler.m` 第 `48-50` 行

它调用：
- `inferTrueClassFromPowers.m` 第 `1-22` 行

这里有一个关键问题：

### 它根本没有看 `Ps`

`inferTrueClassFromPowers.m` 的判决只看：
- `Pi`
- `Pj`
- `Pn`

逻辑是：
- 第 `5-7` 行：如果 `max(Pi,Pj) <= K*Pn`，则判 `none`
- 第 `10-17` 行：如果 `Pj >= Pi`，就按 `InfoCode` 最大分量判 `tone/pbnj/mod`
- 第 `18-20` 行：否则直接判 `mod`

这意味着：
- 只要 jammer 比 co-channel 大，它就会被标成某个 jammer 类
- 即使 `Ps` 远强于 `Pj`，频谱图里 jammer 肉眼都不明显，它仍然可能被标成 `tone` 或 `mod`

这会直接导致：
- `图像看起来像 none`
- `标签却不是 none`

所以很多 `mod -> none` 不是模型完全乱猜，而是：
- `标签定义本身就和图像可分性不一致`

## 3.5 第四层原因：推理样本还使用了 post-AJ 功率

主程序里：
- `LEO_StarNet_EMC_V7_0_Engineering.m` 第 `385-387` 行

设置了：
- `SamplerCfg.UsePostAJPower = true`

这意味着分类输入更偏向：
- 反干扰之后的有效 jammer 功率

而不是：
- 原始未抑制的 jammer 功率

结果就是：
- 一些在“系统事件”上仍被认为是干扰相关的时间点
- 在 STFT 图上已经被 anti-jam 压到很弱
- 模型自然更容易判成 `none`

## 3.6 第五层原因：关键帧不是按“最容易分类”选的，而是按事件选的

关键帧选择在：
- `classifyInterferenceTimeline_powerSampler.m` 第 `23-24` 行

它调用：
- `pickKeyframes(sim.Event, numSteps)`

这意味着导出的 12 张图是：
- 按主仿真事件挑的

而不是：
- 按分类置信度挑的
- 也不是按“最标准的干扰截图”挑的

所以这 12 张图更像：
- `系统事件关键帧`

而不是：
- `分类器 benchmark 样本`

因此：
- 用这 12 张图去代表分类器整体性能，本来就偏苛刻

## 3.7 第六层原因：网络本身也比较浅，训练量也不大

网络结构在：
- `trainLeNetSTFT.m` 第 `19-33` 行

本质上是一个轻量 LeNet。

训练设置在：
- `trainLeNetSTFT.m` 第 `35-42` 行

可以看到：
- `MaxEpochs = 8`
- `MiniBatchSize = 64`

训练集规模在：
- `generateDatasetSimpleSTFT.m` 第 `7` 行

每类只有：
- `train 600`
- `val 120`
- `test 180`

对于这种：
- 频谱混合
- 标签不稳
- 域差明显

的任务来说，这个网络和训练规模都偏保守。

## 4. 所以，问题的本质不是一个，而是三个叠加

## 问题 1：数据是合成的

这是事实。

## 问题 2：训练分布与推理分布不一致

这也是事实，而且是当前识别性能偏低的主因。

## 问题 3：真值定义偏弱

这也是事实，而且直接污染了“正确率”这个指标的解释性。

## 5. 该怎么改

## 5.1 最优先改的，不是网络，而是真值和数据

### 建议 1：把分类任务拆成两步

先做：
- `有无显著干扰` 检测

再做：
- `干扰类型分类`

因为当前最大问题不是 `tone/pbnj/mod` 之间分不开，
而是很多样本连“有没有足够可见的干扰”都不清楚。

### 建议 2：训练集要从主仿真链里采样

不要只用：
- `genSplitSimple.m` 这种规则合成样本

而是要增加：
- 从 `simulateStarNetV7` 最劣场景时间轴里真实抽样
- 用 `PS/PI/PJ/PN` 生成与实际推理域一致的样本

### 建议 3：真值定义必须引入 `Ps`

现在 `inferTrueClassFromPowers.m` 不看 `Ps`，这是不合理的。

应该改成至少同时看：
- `Pj / Ps`
- `Pi / Ps`
- `Pj / Pn`

否则“图上看不见、标签却说有干扰”的冲突会一直存在。

## 5.2 如果暂时不重构，论文里怎么写更稳

如果短期内不改代码，最稳妥的写法是：

- 不把这个识别模块写成严格的“高精度干扰识别器”
- 而把它写成：
  - `基于 STFT 的干扰形态辅助解释模块`
  - `用于辅助展示最劣场景下的时频特征`

这样更符合代码现状，也更不容易被质疑。

## 6. 最后的判断

一句话总结：

`是的，训练样本基本是自己按规则合成出来的；而 12 张关键帧识别率低，核心不是单纯网络太差，而是训练样本、推理样本和标签定义三者并不在同一个问题空间里。`
