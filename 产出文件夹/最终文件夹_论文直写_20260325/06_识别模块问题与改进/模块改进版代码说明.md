# 模块改进版代码说明

## 本次改动原则

- 不改主框架入口
- 不改 `LEO_StarNet_EMC_V7_0_Engineering.m` 的主流程
- 只改干扰识别支链内部模块

## 改动后的代码位置

- `01_工程代码_模块改进版/v7proj`

## 实际改动的文件

### 1. `defaultPowerAlignedSamplerCfg.m`

新增内容：
- `LabelRule`
- `Train`

解决的问题：
- 让标签逻辑有显式门限
- 让训练数据生成范围不再局限于原来的 `JSR = 0~12 dB`

### 2. `inferTrueClassFromPowers.m`

改动方向：
- 原先只看 `Pi / Pj / Pn`
- 现在把 `Ps` 也引入
- 先做“是否有可见干扰”判断，再做类别判断

解决的问题：
- 避免把极弱 jammer 样本硬标成 `tone/mod`
- 缓解“图像看起来是 none，但标签不是 none”的冲突

### 3. `classifyInterferenceTimeline_powerSampler.m`

改动方向：
- 引入分层推理
- 如果功率规则判断当前时刻没有可见干扰，则直接输出 `none`
- 只有在“干扰可见”时才调用 LeNet 分类器

解决的问题：
- 降低由于极弱 jammer 引起的 `false alarm / false mismatch`
- 让分类器只处理更合理的可见干扰样本

### 4. `generateDatasetSimpleSTFT.m`

改动方向：
- 保留 4 类输出
- 但不再沿用原始单模板数据生成思路
- 改成调用与推理同源的 `power-aligned` 合成路径

解决的问题：
- 缓解训练域与推理域不一致

### 5. `genSplitSimple.m`

改动方向：
- 重写数据生成逻辑
- 新增 `buildPowerAlignedTrainingSample(...)`
- 训练集现在包含：
  - 更弱的 JSR
  - 一定范围的 CCI ISR
  - 与推理一致的 `InfoCode` 驱动 jammer 形态

解决的问题：
- 让训练样本更接近真实推理输入

## 这次改动真正解决了什么

### 已经解决的

- 识别模块的问题来源已经被代码级别定位清楚
- 标签逻辑已从“单层硬判”改成“分层规则”
- 训练数据逻辑已改成更接近推理域
- 改前改后关键帧标签对照已经在：
  - `keyframe_old_vs_new_labels.csv`
  - `keyframe_old_vs_new_labels.png`

### 还没有真正重新闭环验证的

由于当前环境没有 `matlab.exe`，所以还没有完成：
- 用改后的模块重新训练 LeNet
- 用改后的模块重新跑 V7
- 导出新的 confusion matrix / keyframes

所以这里要严格区分：

- `代码修改已完成`
- `MATLAB 重新训练与重跑未完成`

## 当前可用的最重要结论

这次改动不是“乱换模型”，而是：
- 先用研究和现有结果证明问题在哪
- 再只在模块内部修正

也就是说，当前改动属于：
- `方法一致性修复`
- `标签逻辑修复`
- `训练/部署域一致性修复`

而不是：
- 另起炉灶换主方法
