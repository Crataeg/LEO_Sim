# 之前图表脚本说明

## 结论

之前我给你整理的那批论文配图，`不是现场重跑 MATLAB 主程序生成的`。

## 实际使用的来源

使用的是工程中已经存在的历史输出：
- `outputs_v7/result_v7.mat`
- `outputs_v7/summary_v7.txt`
- `dataset_stft_r2021a/_exports/` 下已有的 STFT 导出图

然后我写了一个 Python 脚本：
- `scripts/generate_platform_paper_assets.py`

这个脚本做的事情是：
- 读取已有 `result_v7.mat`
- 提取 `DL / UL / E2E` 的吞吐量、中断率、功率项等统计量
- 重新绘制论文风格图
- 复制已有的 STFT 混淆矩阵和关键帧拼图

## 为什么没有直接跑原始 MATLAB

当时环境里没有检测到 `matlab.exe`，所以不能直接调用：
- `run_V7_default.m`
- `LEO_StarNet_EMC_V7_0_Engineering.m`

因此我采取的是：
- `基于现有 MATLAB 结果文件进行二次整理作图`

## 这意味着什么

### 好处

- 图是基于你们原工程已经跑出来的结果，不是我凭空伪造。
- 二次作图过程可复现。

### 限制

- 这不等于重新运行了一遍原始仿真。
- 如果原工程参数改了，旧图不会自动同步，除非重新生成 `result_v7.mat`。

## 当前已保存的位置

- 原脚本已复制到本进化目录：
  - `scripts/generate_platform_paper_assets.py`

## 后续建议

如果后面本机补齐 MATLAB 环境，建议增加一个真正的两段式流程：

1. MATLAB 重跑：
   - 运行 `run_V7_default.m`
   - 重新生成 `result_v7.mat`

2. Python 整理：
   - 用 `generate_platform_paper_assets.py` 统一出论文图

这样论文图链路就会变成：
- 原始仿真结果
- 论文风格二次绘图

这是最稳妥的。
